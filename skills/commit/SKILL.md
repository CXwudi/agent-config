# Commit

1. Inspect changes.
2. Group changes into atomic, reviewable commits by purpose. Keep related changes together and split unrelated changes into separate commits.
3. Format messages as `<gitmoji> <type>(<scope>): <subject>` in imperative mood (e.g., ✨ `feat`, 🐛 `fix`, ♻️ `refactor`, 📝 `docs`), adding a short body or bullet list only for complex changes.

## Notes

- Never commit secrets, API keys, `.env` files, user personal or sensitive information
